💡 Explicación Paso a Paso de fetch()

Aprende qué sucede internamente desde que llamas a la función hasta que muestras los datos en pantalla.

01

Llamada Inicial y Promesas

La función nativa fetch(url) inicia una petición HTTP asíncrona hacia el endpoint especificado. Retorna inmediatamente un objeto Promise.

const respuesta = await fetch('https://restcountries.com/v3.1/name/nicaragua');
02

Objeto Response & Estado HTTP

La promesa de fetch devuelve un objeto Response con metadatos del servidor. Siempre debemos verificar si la respuesta fue satisfactoria usando la propiedad response.ok.

if (!respuesta.ok) throw new Error('Error HTTP: ' + respuesta.status);
03

Lectura y Parseo a JSON

Para procesar el cuerpo de la respuesta en formato JSON, llamamos a response.json(). REST Countries retorna una lista de países coincidentes.

const [pais] = await respuesta.json();
04

Manejo de Errores con try...catch

Es fundamental envolver las llamadas asíncronas en un bloque try...catch para gestionar fallos de red, caídas del servicio o países no encontrados.

try { /* fetch */ } catch (error) { console.error(error); }

⚔️ Comparativa de Sintaxis: async/await vs .then()

Ambos enfoques resuelven promesas de forma asíncrona, pero async/await proporciona una sintaxis más limpia y secuencial.

✨ Opción 1: Sintaxis Moderna (async / await) 
async function obtenerPais() {
  try {
    // 1. Ejecutar petición HTTP
    const res = await fetch('https://restcountries.com/v3.1/name/nicaragua');
    
    // 2. Validar estado de la respuesta
    if (!res.ok) {
      throw new Error(`Error HTTP: ${res.status}`);
    }

    // 3. Parsear JSON (obtenemos el primer resultado)
    const [pais] = await res.json();
    
    // 4. Utilizar los datos recibidos
    console.log('País:', pais.name.common);
    console.log('Capital:', pais.capital[0]);
  } catch (error) {
    console.error('Ocurrió un error:', error.message);
  }
}
📜 Opción 2: Promesas Clásicas (.then / .catch) 
function obtenerPaisConPromesas() {
  // 1. Iniciar la petición fetch
  fetch('https://restcountries.com/v3.1/name/nicaragua')
    .then(res => {
      // 2. Validar respuesta HTTP
      if (!res.ok) {
        throw new Error(`Error HTTP: ${res.status}`);
      }
      // 3. Retornar promesa de JSON
      return res.json();
    })
    .then(dataList => {
      // 4. Tomar el país resultante
      const pais = dataList[0];
      console.log('País:', pais.name.common);
      console.log('Capital:', pais.capital[0]);
    })
    .catch(error => {
      console.error('Ocurrió un error:', error.message);
    });
}

⚠️ Detalles Clave & Buenas Prácticas al usar fetch()

🛑

1. Fetch NO rechaza por 404 o 500

A diferencia de librerías como Axios, fetch() solo rechaza la promesa si ocurre un error físico de red (sin internet o fallo DNS). Respuestas como 404 Not Found se resuelven con response.ok = false.

⏳

2. Dos Promesas en el proceso

Hay dos pasos asíncronos secuenciales: primero esperar la respuesta inicial de red (fetch), y después esperar la decodificación completa del cuerpo (response.json()).

📤

3. Enviar Datos (POST, PUT, DELETE)

Por defecto fetch utiliza el método GET. Para enviar información se define el segundo parámetro con method, encabezados (Content-Type) y cuerpo serializado con JSON.stringify().

🔒

4. Políticas CORS Habilitadas

REST Countries es un servicio abierto con cabeceras CORS habilitadas (Access-Control-Allow-Origin: *), permitiendo peticiones directas desde el navegador sin necesidad de proxies intermedios.
